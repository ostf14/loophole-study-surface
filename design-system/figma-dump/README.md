# LO Design System Dump

Плагин Figma, снимающий из файла `LO Design System (FSH Update)` то, чего не
отдаёт REST на нашем тарифе. Выполняется внутри Figma, поэтому не зависит ни
от квот REST, ни от квот MCP, ни от типа места. Файл не меняет — только читает.

## Зачем

REST даёт геометрию, но берёт квоту и на Professional выбивается за сутки.
Панель свойств даёт точные числа, но по одному компоненту за раз. Плагин
снимает весь файл за один прогон и добывает то, что иначе недоступно:

- **имя текстового стиля на конкретном слое** (`textStyleId` → имя). Именно
  этой привязки не хватало, чтобы понять, чем размечен слой, а не какие у
  него числа;
- **`visible` у каждого эффекта** — выключенная тень лежит в массиве и через
  REST читается как настоящая. На этом мы ошиблись дважды;
- **порядок и относительные позиции слоёв** — тень у них часто нарисована
  фигурой со сдвигом, а не эффектом;
- **компонент против инстанса** через `getMainComponentAsync`, а не по
  догадке: инстанс несёт переопределения под своё место;
- **`componentPropertyDefinitions`** — свойства, варианты и значения по
  умолчанию.

Переменные снимаются попыткой: если тариф их не отдаёт, в дампе окажется
`variables: { error: … }`, и прогон не сломается. Примитивный слой при этом
уже снят вручную и лежит в `../INVENTORY.md`.

## Запуск

1. Figma → **Plugins → Development → Import plugin from manifest…**
2. Указать `manifest.json` из этой папки.
3. Открыть файл дизайн-системы, запустить плагин, дождаться «Готово».
4. **Скачать JSON** — и положить рядом, в `design-system/`.

Работает и в Dev Mode. Права на запись не нужны: плагин ничего не пишет.

## Что внутри дампа

```
file, generatedAt
textStyles[]    имя, кегль, начертание, интерлиньяж, трекинг, регистр
paintStyles[]   имя, заливки
effectStyles[]  имя, эффекты с visible
variables[]     если тариф отдаёт; иначе { error }
components[]    имя, страница, геометрия, layout, обводки, заливки,
                эффекты с visible, свойства, дерево детей до 4 уровней;
                у текстовых слоёв — привязанный стиль
```

Глубина обхода и обрезка текста — константы `MAX_DEPTH` и `MAX_CHARS`
в начале `code.js`. В дампе есть `secondsByStep` — сколько секунд занял
каждый шаг; если прогон вдруг снова затянется, сначала смотреть туда.

## Что стоило первого прогона

Первая версия шла **4000 секунд**. Причина одна: на каждом инстансе
вызывался `getMainComponentAsync`, чтобы записать имя главного компонента.
Это запрос через мост, и если инстанс ссылается на опубликованную
библиотеку — а в файле с суффиксом «(Copy)» так и есть, — запрос уходит
наружу. Замерено 1.44 секунды на вызов, инстансов 2776, итого 67 минут:
весь прогон целиком ради поля, которое почти всегда повторяет `name` самого
инстанса.

Убрано вместе с ещё тремя вещами: внутрь инстансов больше не спускаемся
(их поддерево — копия главного компонента, который дампится отдельно, это
4010 узлов из 15706), управление уступается по времени, а не по счётчику
компонентов, и JSON больше не форматируется отступами.
